Tic-Tac-Toe Game

OVERVIEW

What Is This Project?

The Game

  • Classic 3×3 Tic-Tac-Toe played in the terminal
  • Human player (X) vs Artificial Intelligence (O)
  • Human picks a row and column; AI picks its own best move
  • First to get 3 in a row wins; full board with no winner is a draw

The AI Modes

  • Rule-Based — follows a priority checklist (beginner–medium)
  • Heuristic — scores each possible move with a formula (medium–hard)
  • Minimax — searches the entire game tree (unbeatable)

Player chooses the AI mode at the start of each game.

The real goal of this project is not just to play Tic-Tac-Toe — it is to demonstrate software design patterns in a practical, understandable setting.

GAME FLOW

How a Game Plays Out — Step by Step

1
Launch — Main.main() creates a Game and calls start().
2
Choose AI Mode — The game shows a menu (Rule-Based / Heuristic / Minimax). Player types 1, 2, or 3. AIStrategyFactory.createStrategy("minimax") → new MinimaxStrategy()
3
Create Players — HumanPlayer (symbol X) and AIPlayer (symbol O, holds the chosen strategy).
4
Game Loop — Repeats until someone wins or board is full:
  1. Current player's getMove(board) is called → returns a Move
  2. Board.makeMove(row, col, symbol) places the symbol
  3. Board.display() prints the updated board
  4. Check Board.isWin() and Board.isDraw()
  5. Switch the current player
5
Game Over — Print the result (win for X, win for O, or draw) and exit.
DESIGN PATTERN

Design Pattern #1 — Strategy

What Is It?

The Strategy pattern defines a family of algorithms, encapsulates each one, and makes them interchangeable. The client (AIPlayer) doesn't need to know how the algorithm works — it just calls it.

Why Use It Here?

  • We have 3 different AI algorithms
  • The game loop is identical regardless of which AI is used
  • Adding a 4th algorithm requires zero changes to existing code
  • Demonstrates the Open/Closed Principle

Structure in This Project

DESIGN PATTERN

Design Pattern #2 — Factory

What Is It?

The Factory pattern provides a single place to create objects without exposing the instantiation logic to the rest of the code. Instead of calling new MinimaxStrategy() everywhere, you ask the factory.

Why Use It Here?

  • Decouples the Game class from concrete strategy classes
  • One place to add new strategies — no need to search the codebase
  • The Game class only knows the interface, never the implementation

Real Benefit

If you later rename MinimaxStrategy, you only fix one line in the factory — not every place in the code that creates it.

public class AIStrategyFactory {

  public static AIStrategy createStrategy(
          String type) {

    switch (type.toLowerCase()) {

      case "rule-based":
        return new RuleBasedStrategy();

      case "minimax":
        return new MinimaxStrategy();

      case "heuristic":
        return new HeuristicStrategy();

      default:
        throw new IllegalArgumentException(
          "Unknown strategy: " + type);
    }
  }
}
DESIGN PATTERN

Design Pattern #3 — Template Method (via Abstract Class)

What Is It?

An abstract base class defines a skeleton behaviour (the template) and forces subclasses to fill in the specific details. The overall structure is fixed; only the variable part is overridden.

In This Project

  • Player is the abstract class
  • It defines the player's symbol and the contract: getMove(Board)
  • HumanPlayer overrides it with keyboard input
  • AIPlayer overrides it with a strategy call
  • The Game class treats both identically — it just calls player.getMove(board)
// Abstract base — the template
public abstract class Player {
  protected Cell symbol;

  public abstract Move getMove(Board board);
}

// HumanPlayer — one implementation
public class HumanPlayer extends Player {
  public Move getMove(Board board) {
    // reads keyboard input, validates, returns Move
  }
}

// AIPlayer — another implementation
public class AIPlayer extends Player {
  public Move getMove(Board board) {
    return strategy.chooseMove(board, symbol);
  }
}

// Game — doesn't care which player type it is
Move move = current.getMove(board);

Benefit: The game loop never changes when you add a new player type. Just extend Player.

AI STRATEGY 1 / 3

Rule-Based Strategy — Priority Checklist

The AI works through a fixed priority list and picks the first rule that applies. No calculation, no lookahead — just conditional checks.

1
Win if possible

Check every empty cell — if placing O there creates 3-in-a-row, take it.

2
Block opponent's win

Check every empty cell — if placing X there would win, block it.

3
Take the center

Position (1,1) controls the most lines. Take it if free.

4
Take a corner

Corners (0,0), (0,2), (2,0), (2,2) are the next best positions.

5
Take any cell

Fallback — pick any remaining empty cell.

Strengths

  • Very fast — checks at most ~10 cells
  • Easy to understand and explain
  • Handles all obvious threats

Weaknesses

  • No lookahead — can't spot traps 2 moves ahead
  • A skilled player can set up a fork and win

Rating

Beginner – Medium

Good enough to beat a careless player; beatable by a careful one.

AI STRATEGY 2 / 3

Minimax Strategy — The Unbeatable AI

The Core Idea

Minimax simulates every possible game from the current position to the end. It assumes the human plays perfectly and finds the move that is guaranteed to give the AI the best possible outcome.

Scoring

  • AI wins → score = +10
  • Human wins → score = −10
  • Draw → score = 0

Rating

Unbeatable

Mathematically proven — the human cannot win. Best result is a draw.

private int minimax(Board board,
        boolean isMaximizing,
        Cell ai, Cell opp) {

  // Base cases — game is over
  if (board.isWin(ai))   return  10;
  if (board.isWin(opp))  return -10;
  if (board.isDraw())    return   0;

  if (isMaximizing) {  // AI's turn
    int best = Integer.MIN_VALUE;
    for (Move m : board.getEmptyCells()) {
      board.makeMove(m, ai);
      best = Math.max(best,
               minimax(board, false, ai, opp));
      board.undoMove(m);  // backtrack
    }
    return best;
  } else {             // Human's turn
    int best = Integer.MAX_VALUE;
    for (Move m : board.getEmptyCells()) {
      board.makeMove(m, opp);
      best = Math.min(best,
               minimax(board, true, ai, opp));
      board.undoMove(m);
    }
    return best;
  }
}

On the first move, minimax explores up to 9! = 362,880 possible game endings. Still fast because many branches are identical or pruned early.

AI STRATEGY 3 / 3

Heuristic Strategy — Score-Based Evaluation

The Core Idea

Instead of searching the full game tree, the heuristic scores each empty cell using a formula and picks the highest-scoring one. Fast and smart — but not perfect.

Scoring Formula for Each Move

Positional bonus:
  • Center (1,1): +0.4
  • Corner: +0.2
  • Edge: +0
Line bonus (per row/col/diagonal through this cell):
  • AI already has 2 in this line: +0.9 (win!)
  • Opponent has 2 in this line: +0.9 (block!)
  • AI has 1 in this line: +0.3
  • Line is mixed (both present): 0

Example — Why Center Wins Early

The center cell participates in 4 lines (row, col, 2 diagonals). Corner cells participate in 3 lines. Edge cells in only 2. More lines = more strategic value — the formula captures this automatically.

Draw Condition

A draw happens when all 9 cells are filled AND no winning line exists. The isDraw() method checks this by verifying getEmptyCells().isEmpty() and that neither player has won.

public boolean isWin(Cell cell) {

  // Check 3 rows and 3 columns
  for (int i = 0; i < 3; i++) {

    // Row i: all three cells in row i match?
    if (cells[i][0] == cell
        && cells[i][1] == cell
        && cells[i][2] == cell)  return true;

    // Column i: all three cells in column i match?
    if (cells[0][i] == cell
        && cells[1][i] == cell
        && cells[2][i] == cell)  return true;
  }

  // Main diagonal: top-left → bottom-right
  if (cells[0][0] == cell && cells[1][1] == cell
      && cells[2][2] == cell)      return true;

  // Anti-diagonal: top-right → bottom-left
  if (cells[0][2] == cell && cells[1][1] == cell
      && cells[2][0] == cell)      return true;

  return false; // no winner found
}
EXTENSIBILITY

Adding a New AI Strategy — 2 Steps, Zero Breakage

One of the key goals of this design is that it's open for extension — adding new features doesn't require touching existing, working code.

1

Create the new strategy class

public class AlphaBetaStrategy
        implements AIStrategy {

  public Move chooseMove(
          Board board, Cell symbol) {
    // ... new algorithm here ...
  }
}
2

Add one case to the factory

case "alpha-beta":
    return new AlphaBetaStrategy();

What Does NOT Change

  • Board.java — untouched
  • Player.java — untouched
  • AIPlayer.java — untouched
  • Game.java — untouched
  • Main.java — untouched

This Is the Open/Closed Principle

"Software entities should be open for extension, but closed for modification."

By programming to the AIStrategy interface, the game is designed to grow without touching existing code — reducing the chance of introducing new bugs.
